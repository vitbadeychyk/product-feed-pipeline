# Документація інтеграції Rozetka

## 1. Призначення

Модуль Rozetka автоматично формує XML-фід товарів для завантаження в
PriceCreator Rozetka.

Основні задачі:

-   читання товарів із загального фіда постачальника;
-   формування XML Rozetka;
-   розрахунок продажної ціни;
-   формування старої ціни;
-   округлення цін;
-   застосування різних формул ціноутворення залежно від категорії;
-   використання ID категорій Rozetka там, де вони вже визначені;
-   використання ID категорії постачальника як fallback;
-   передача описів і характеристик;
-   автоматичне додавання гарантії;
-   автоматичне оновлення XML через GitHub Actions.

------------------------------------------------------------------------

## 2. Структура файлів

``` text
product-feed-pipeline/
│
├── scripts/
│   ├── pricing/
│   │   └── rozetka_pricing.py
│   │
│   └── rozetka/
│       ├── export_feed.py
│       └── category_map.py
│
└── data/
    └── output/
        └── rozetka/
            └── rozetka_feed.xml
```

### `scripts/rozetka/export_feed.py`

Основний генератор XML.

Відповідає за:

-   читання товарів;
-   формування `<offer>`;
-   назву;
-   опис;
-   фотографії;
-   категорію;
-   ціну;
-   стару ціну;
-   характеристики;
-   гарантію;
-   запис фінального XML.

### `scripts/pricing/rozetka_pricing.py`

Окремий калькулятор цін Rozetka.

Відповідає за:

-   визначення формули відповідно до категорії;
-   розрахунок продажної ціни;
-   fallback для категорій без окремої формули;
-   округлення до 100 грн;
-   розрахунок старої ціни.

### `scripts/rozetka/category_map.py`

Таблиця відповідності:

``` text
ID категорії постачальника
        ↓
ID категорії Rozetka
```

Це потрібно, щоб для вже прив'язаних категорій передавати правильний ID
Rozetka та не створювати зайві дублікати категорій у PriceCreator.

## 3. Загальна схема роботи

``` text
supplier_feed.xml
        ↓

        ↓
ID категорії постачальника
        │
        ├──────────────→ rozetka_pricing.py
        │                       ↓
        │                 розрахунок price
        │                 розрахунок price_old
        │
        └──────────────→ category_map.py
                                ↓

                                ↓
                         export_feed.py
                                ↓
                        rozetka_feed.xml
                                ↓
                       PriceCreator Rozetka
```

## 4. Два різних ID категорії

У системі важливо розрізняти:

1.  **ID категорії постачальника** - використовується для бізнес-логіки
    та калькулятора ціни.
2.  **ID категорії Rozetka** - використовується для передачі категорії у
    фінальний XML, якщо відповідність уже відома.

### Приклад

Біговели:

``` text
ID постачальника = 491
ID Rozetka       = 4674205
```

Для калькулятора:

``` python
calculate_price(
    original_price=original_price,
    category_id="491",
)
```

У фінальному XML:

``` xml
<categoryId>4674205</categoryId>
```

**Важливо:** ID Rozetka не повинен замінювати ID постачальника всередині
калькулятора.

## 6. Логіка вибору categoryId для XML

Якщо для ID постачальника є відповідність у `ROZETKA_CATEGORY_MAP`, у
XML передається ID Rozetka.

Якщо відповідності немає, передається ID постачальника.

``` python
def get_rozetka_category_id(supplier_category_id: str) -> str:
    supplier_category_id = str(supplier_category_id or "").strip()

    return ROZETKA_CATEGORY_MAP.get(
        supplier_category_id,
        supplier_category_id,
    )
```

### Приклад з прив'язкою

``` text
Біговели
ID постачальника = 491
ID Rozetka = 4674205
```

Результат:

``` xml
<categoryId>4674205</categoryId>
```

``` text

ID Rozetka = не визначено
```

Результат:


# Ціноутворення

## 9. Загальний принцип

Калькулятор знаходиться:

``` text
scripts/pricing/rozetka_pricing.py
```

Послідовність:

``` text
ціна постачальника
        ↓
визначення categoryId постачальника
        ↓
пошук формули категорії
        ↓
розрахунок фінальної ціни
        ↓
округлення ВГОРУ до 100 грн
        ↓
price
        ↓
+30%
        ↓
округлення ВГОРУ до 100 грн
        ↓
price_old
```

------------------------------------------------------------------------

## 10. Округлення

Фінальна ціна завжди округлюється **вгору до найближчих 100 грн**.

``` python
def round_up_to_100(price: float) -> float:
    if price <= 0:
        return 0.0

    return float(math.ceil(price / 100.0) * 100)
```

Приклади:

    Розрахована ціна   Результат
  ------------------ -----------
                1201        1300
                1299        1300
                1300        1300
                1301        1400
                9999       10000

Це не звичайне математичне округлення - значення завжди округлюється
вгору.

------------------------------------------------------------------------

## 11. Стара ціна

Стара ціна:

``` text
price_old = price + 30%
```

Після цього також округлюється вгору до 100 грн.

``` python
def calculate_old_price(final_price: float) -> float:
    if final_price <= 0:
        return 0.0

    return round_up_to_100(final_price * 1.30)
```

Приклад:

``` text
price = 5600

5600 × 1.30 = 7280
округлення → 7300
```

XML:

``` xml
<price>5600</price>
<price_old>7300</price_old>
```

## 22. Fallback для категорій без формули

Якщо категорія відсутня в `CATEGORY_PRICING_RULES`, використовується
універсальна формула:

``` text
ціна постачальника + 500 грн
```

Після цього результат округлюється вгору до 100 грн.

``` python
if rule is None:
    calculated_price = original_price + 500
```

Приклад:

``` text
ціна постачальника = 1234
+500 = 1734
округлення → 1800
```

Далі:

``` text
price = 1800
price_old = 1800 × 1.30 = 2340
округлення → 2400
```

Результат:

``` xml
<price>1800</price>
<price_old>2400</price_old>
```

# Формування XML

## 23. Розрахунок ціни в export_feed.py

Основний генератор викликає:

``` python
final_price = calculate_price(
    original_price=original_price,
    category_id=category_id,
)

old_price = calculate_old_price(
    final_price
)
```

`category_id` тут - ID категорії постачальника.

------------------------------------------------------------------------

## 24. Формування categoryId

Спочатку читається ID постачальника:

``` python
category_id = get_text(
    item,
    "categoryId",
)
```

Після цього визначається ID для XML:

``` python
xml_category_id = get_rozetka_category_id(
    category_id
)
```

І у фінальний XML записується:

``` python
ET.SubElement(
    offer,
    "categoryId",
).text = xml_category_id
```

------------------------------------------------------------------------

## 25. Формування price та price_old

У XML передаються два поля:

``` xml
<price>...</price>
<price_old>...</price_old>
```

Наприклад:

``` xml
<price>1300</price>
<price_old>1700</price_old>
```

------------------------------------------------------------------------

## 26. Гарантія

Для товарів автоматично додається:

``` xml
<param name="Гарантія">12 місяців</param>
```

Щоб не створювати дублікати, параметри постачальника з назвами:

``` text
Гарантія
Гарантия
Warranty
```

пропускаються, після чого додається єдиний стандартний параметр:

``` text
Гарантія = 12 місяців
```

------------------------------------------------------------------------

## 27. Описи товарів

Опис форматується для PriceCreator за допомогою HTML.

Використовуються:

``` html
<p>...</p>
<strong>...</strong>
<ul>
    <li>...</li>
</ul>
```

Звичайний текст перетворюється на абзаци, а пункти з маркером `•` - на
HTML-списки.

### Екранування HTML у XML

У raw XML можна побачити:

``` xml
<description>&lt;p&gt;Текст&lt;/p&gt;</description>
```

Це нормальна поведінка XML.

XML екранує:

``` text
< → &lt;
> → &gt;
```

Після XML-парсингу отримувач отримує HTML:

``` html
<p>Текст</p>
```

Тому вручну змінювати `&lt;` або `&gt;` не потрібно.

------------------------------------------------------------------------

# Автоматизація

## 29. GitHub Actions

Основний генератор запускається командою:

``` bash
python -m scripts.rozetka.export_feed
```

Окремо запускати:

``` text
rozetka_pricing.py
category_map.py
```

не потрібно.

`export_feed.py` сам імпортує ці модулі.

------------------------------------------------------------------------

## 30. Загальна послідовність автоматичного оновлення

``` text
GitHub Actions
      ↓
читання supplier feed

інші обробки pipeline
      ↓
python -m scripts.rozetka.export_feed
      ↓

      ↓

      ↓
створення rozetka_feed.xml
      ↓

      ↓

      ↓
оновлений RAW XML
      ↓

```

Фінальний XML:

``` text
data/output/rozetka/rozetka_feed.xml
```

# Подальші зміни

## 31. Якщо потрібно змінити формулу ціни

Редагувати:

``` text
scripts/pricing/rozetka_pricing.py
```

Наприклад:

``` python
def avtokrisla(price):
    ...
```

`export_feed.py` для зміни націнки редагувати не потрібно.

------------------------------------------------------------------------

## 32. Якщо потрібно додати нову формулу

Створити нову функцію:

``` python
def zapchastyny(price):
    price *= 0.78
    price += 500
    return price
```

Після цього додати відповідність у:

``` python
CATEGORY_PRICING_RULES
```

Наприклад:

``` python
"195": zapchastyny,
```

Після цього категорія `195` автоматично використовуватиме нову формулу.

------------------------------------------------------------------------

## 33. Якщо потрібно змінити ID Rozetka

Редагувати тільки:

``` text
scripts/rozetka/category_map.py
```

Наприклад:

``` python
"195": "1234567",  # Запчастини
```

Калькулятор продовжить використовувати:

``` text
195
```

а у XML буде:

``` xml
<categoryId>1234567</categoryId>
```

------------------------------------------------------------------------

## 34. Якщо ID Rozetka відсутній

Нічого додатково робити не потрібно.

Наприклад:

``` text
ID постачальника = 195
ID Rozetka = не визначено
```

Якщо `195` відсутній у `ROZETKA_CATEGORY_MAP`, у XML автоматично
передається:

``` xml
<categoryId>195</categoryId>
```

Коли ID Rozetka буде визначений, достатньо додати його в
`category_map.py`.

``` text
supplier price
      ↓
+500 грн
      ↓
округлення вгору до 100
      ↓
price
      ↓
+30%
      ↓
округлення вгору до 100
      ↓
price_old
```

# 42. Поточний базовий принцип інтеграції

> **ID постачальника використовується для бізнес-логіки та
> калькулятора.**
>
> **ID Rozetka використовується для передачі категорії у XML.**
>
> **Якщо ID Rozetka відсутній - використовується ID постачальника.**
>
> **Якщо окрема формула ціни для категорії відсутня - до ціни
> постачальника додається 500 грн.**
>
> **Фінальна ціна округлюється вгору до найближчих 100 грн.**
>
> **`price_old` = `price` + 30% та також округлюється вгору до
> найближчих 100 грн.**
>
> **Гарантія для товарів передається як `12 місяців`.**
